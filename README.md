# Kokonut_Sync

에고버스 전용 Paper 26.3 플레이어 데이터 동기화 플러그인.

- Core와 동일한 버전: `cbt-1.0`, 작성자: `pingpong`, 웹사이트: https://wiki.egoverse.kr
- `Kokonut-Core` 필수. SQL은 CoreDatabase 서비스를 사용하며 Redis 접속 설정은 Core의 RedisSettings를 사용합니다.
- 설정은 Settings 클래스 기본값, 메시지는 JAR 내 한국어 리소스를 사용합니다. 로컬 config.yml/messages/server.yml을 읽거나 생성하지 않습니다.
- 서버 ID는 월드 로딩 후 서버의 첫 번째(메인) 월드 이름입니다. 각 서버의 메인 월드 이름은 서로 달라야 합니다.
- Fabric, 다른 Minecraft 버전, 업데이트 확인, bStats, Plan, ProtocolLib, PacketEvents, 외부 데이터 마이그레이터를 제거했습니다.

빌드: `gradlew.bat :common:test :bukkit:26.3:build`

Core JAR 기본 경로는 `../core/Kokonut_Core/build/libs/Kokonut-Core-cbt-1.0.jar`이며 `-PcoreJar=경로`로 지정할 수 있습니다.
산출물: `target/Kokonut_Sync-Bukkit-cbt-1.0+mc.26.3.jar`.

HuskSync 기반 포크이며 원본 저작권 및 Apache-2.0 라이선스는 유지합니다.

## 한국어 명령어와 시스템 메시지

- `/동기화 [정보|상태|다시불러오기|추출 확인|구형자료변환]`
- `/동기화데이터 조회 <플레이어> [스냅샷]`
- `/동기화데이터 목록 <플레이어> [페이지]`
- `/동기화데이터 저장 <플레이어>`
- `/동기화데이터 삭제|복원|고정 <플레이어> <스냅샷>`
- `/동기화데이터 추출 <플레이어> [<스냅샷> <웹|파일>]`
- `/동기화인벤토리 <플레이어> [스냅샷]`
- `/동기화엔더상자 <플레이어> [스냅샷]`

Core의 `/invsee`, `/ec`와 충돌하지 않도록 동기화 관리 명령어에는 별도의 한국어 이름을 사용합니다.
권한 노드는 기존 `husksync.command.*`를 유지합니다. 채팅 응답은 Core `MessageUtil.send`를 사용하여 시스템 양식·클라이언트 전달·한국어 글꼴을 적용합니다. 액션바 알림은 sync 내부에서 메시지를 MiniMessage로 직접 파싱하여 전송합니다. Core의 채팅용 시스템 양식은 적용하지 않습니다.

## 현재 내장 설정값

아래는 이전 config.yml 항목에 해당하는 현재 코드 기본값입니다. 설정 파일로 저장하거나 읽지 않습니다. 변경하려면 `Settings.java` 또는 `Identifier.java`를 수정하고 다시 빌드해야 합니다. 다시불러오기는 내장 기본값을 다시 적용하며 JAR의 값을 수정하지 않습니다.

| 항목 | 현재 값 |
| --- | --- |
| 언어 | 한국어 (`ko-kr`) |

| 디버그 로그 | 꺼짐 |
| 비활성화 명령어 | 없음 |
| 서버 이름 | 첫 번째 메인 월드 이름 |

| 테이블 자동 생성 | 켜짐 |

| 동기화 방식 | LOCKSTEP (잠금 동기화) |
| 플레이어당 회전 대상 백업 수 | 16개 (고정한 백업은 회전 대상 제외) |

| 이벤트 우선순위 | 접속 LOWEST, 종료 LOWEST, 사망 NORMAL |

### 동기화 대상

인벤토리, 엔더 상자, 영속 데이터(PDC), 발전 과제, 통계, 포션 효과, 게임 모드, 비행 상태, 속성, 체력, 허기, 경험치는 켜짐입니다. **위치 동기화는 꺼짐**입니다. 사용자 정의 데이터는 등록 시 기본 동기화 대상입니다.

동기화하는 속성은 최대 체력, 최대 흡수량, 행운, 크기, 단차 높이, 중력입니다. `minecraft:generic.*` 형태의 기존 식별자도 목록에 남아 있습니다. 속성 수정자 중 `minecraft:effect.*`, `minecraft:creative_mode_*`는 제외합니다.

### Redis 연결 옵션

접속 주소·포트·사용자·비밀번호·DB 번호는 Core의 `RedisSettings`에서 가져오며 여기에 복제하지 않습니다.

| 항목 | 현재 값 |
| --- | --- |
| SSL/TLS | 꺼짐 |
| 연결 / 소켓 타임아웃 | 각각 2,000ms |
| 최대 연결 수 | 50 |
| 최대 / 최소 유휴 연결 수 | 8 / 2 |
| 연결 대여 / 반환 / 유휴 검사 | 모두 켜짐 |
| 유휴 연결 제거 기준 | 60,000ms |
| 유휴 검사 간격 | 30,000ms |
| 명령 재시도 | 최대 3회 |
| 재시도 대기 | 200ms |
| Sentinel | 사용 안 함 (마스터·노드·비밀번호 비어 있음) |
